Add fuzz testing for shared type decoding and input validation (Issue #90)

OVERVIEW
========
Implemented comprehensive fuzz testing infrastructure to prove that malformed input
to shared types (ProofRecord, IssuerRecord, IssuerStatus, ProofStatus) and entry
point parameters is always rejected gracefully with proper error codes, never
causing panics, traps, or undefined behavior.

DELIVERABLES
============

1. Fuzz Targets (6 new):
   - fuzz/fuzz_targets/fuzz_proof_record_decode.rs (ProofRecord XDR deserialization)
   - fuzz/fuzz_targets/fuzz_issuer_record_decode.rs (IssuerRecord XDR deserialization)
   - fuzz/fuzz_targets/fuzz_issuer_status_decode.rs (IssuerStatus enum discriminants)
   - fuzz/fuzz_targets/fuzz_proof_status_decode.rs (ProofStatus enum discriminants)
   - fuzz/fuzz_targets/fuzz_address_validation.rs (Address validation functions)
   - fuzz/fuzz_targets/fuzz_entry_point_register_proof.rs (Entry point parameters)

2. Corpus Seeding (6 directories with documentation):
   - fuzz/corpus/fuzz_proof_record_decode/ + README

   - fuzz/corpus/fuzz_proof_status_decode/ + README

   Each corpus includes documented test cases (valid, boundary, invalid, malformed)

COVERAGE
========

Shared Types:
- ProofRecord: 8 fields (id/commitment hashes, status, schema_version, expires_at, created_at, revoked_at)
- IssuerRecord: 6 fields (id/metadata hashes, status, created_at, updated_at)
- IssuerStatus: 3-variant enum (Active, Suspended, Revoked)
- ProofStatus: 2-variant enum (Active, Revoked)

Entry Points:
- proof-registry::register_proof(): schema_version (u32 > 0), expires_at (u64 > now), issuer_address

Validation Functions:
- packages/shared::is_valid_principal_address(): 56 chars, [A-Z2-7], not all-A
- packages/shared::is_zero_or_sentinel_address(): all-A detection

Boundary Cases:
- schema_version = 0 (invalid)
- expires_at = 0 (past/now, invalid)
- enum discriminants out of range
- address strings: too short, too long, invalid charset
- all-zero and all-0xFF field values
- malformed input: < minimum length, > maximum length

CONSTRAINTS
===========

- No panics in production code: If fuzzing surfaces a panic, it's a bug to fix, not a target to weaken
- No state corruption: Fuzz targets verify no storage changes on invalid input
- Bounded memory: Skip inputs > 8KB to prevent exhaustion
- No cross-contract fuzzing: Covered by integration tests in tests/cross-contract/
- Deterministic corpus: Seeded inputs for reproducibility, deeper campaigns run locally
- Nightly-only: Requires nightly toolchain for libFuzzer and ASan
